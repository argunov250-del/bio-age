# Сервер Хирона

Своя модель на открытой базе Qwen3 (Apache-2.0), дообученная LoRA на каталоге Epimely. Приложение зовёт сервер и, если его нет, отвечает каталогом. Аккаунты и ключи этим репозиторием не создаются.

Qwen3-4B уже используется в приложении и лицензия Apache-2.0. Для ответа «как в чате» на одной видеокарте 24 ГБ лучше **Qwen3-8B**: она заметно ровнее держит тон и два языка, а на vLLM всё ещё быстрая. Qwen3-4B берите, если учите на бесплатном Colab T4 (16 ГБ) или сервер на карте 16 ГБ. Качество 8B выше, скорость 4B выше; ни та ни другая не равна GPT-4 по знаниям.

Цифры ниже — порядок величины по публичным замерам vLLM на одной потребительской карте, не замер этого репозитория.

| Модель | Карта | Первый токен | Генерация | Короткий ответ |
| --- | --- | --- | --- | --- |
| Qwen3-4B | RTX 4090 24 ГБ, vLLM | ~50–150 мс | ~80–150 ток/с | обычно меньше 2 с |
| Qwen3-8B | RTX 4090 / A10 / L4 24 ГБ, vLLM | ~80–200 мс | ~50–100 ток/с | обычно 2–4 с |
| Qwen3-8B GGUF Q4_K_M | та же карта, llama.cpp | медленнее vLLM | ~30–60 ток/с | дешевле по возне, хуже по скорости |

## Деньги (оценка, не счёт)

Один прогон обучения на арендованной 24 ГБ — около 1–2 часов для 8B и меньше часа для 4B. По типичным ценам RunPod/Modal это несколько долларов за прогон, не абонентка.

Сервер, который отвечает сразу (без холодного старта):

- RunPod RTX 4090 или L4/A10 24 ГБ, если оставить включённым круглые сутки: примерно 0,30–0,80 $ в час, то есть около 220–580 $ в месяц. Спот дешевле и может оборваться.
- Modal считает по секундам. Пока контейнер тёплый, порядок тот же. Если гасить в простое, месяц дешевле, но первый вопрос после паузы ждёт старта GPU десятки секунд и «как ChatGPT» уже не ощущается.

Бесплатный CPU этот темп не держит. Его в этот путь не ставим.

## Что сделать владельцу

1. Положить свой Hugging Face token в секрет Colab или Kaggle с именем `HF_TOKEN` (ноутбук читает только оттуда, в файл токен не пишется). Запустить `train_colab.ipynb`. Адаптер уходит в `MaksimSun/chiron-qwen3-lora`, GGUF Q4_K_M — в `MaksimSun/chiron-qwen3-gguf`.
2. Собрать образ `chiron-server` на машине с GPU и поднять его. `CHIRON_KEY` — длинная случайная строка. По умолчанию база `Qwen/Qwen3-8B` и LoRA `MaksimSun/chiron-qwen3-lora` (имя модели для API — `chiron`). Если карта 16 ГБ, `MODEL=Qwen/Qwen3-4B`. Для llama.cpp скачать GGUF из `MaksimSun/chiron-qwen3-gguf`.
3. В GitHub → Settings → Secrets добавить `CHIRON_URL` (публичный `https://…`) и `CHIRON_KEY`. Сборка APK подставит их в `lib/chironConfig.js`. Пока секретов нет, приложение молча отвечает каталогом и в сеть не ходит.

## Датасет

`npx jest --config chiron-server/jest.config.js`

Пишет `data/train.jsonl` и `data/val.jsonl`. Источники: `answerQuestion` по каталогу `lib/coach/qa` (ru и en, источники, перефразировки вопроса) и готовые отказы из `lib/coach/scenarios` (`sensitive`, `cap_diagnose`). Валидация — каждый десятый пример по хэшу реплики.

В ноутбуке после обучения печатаются несколько отложенных вопросов. Для строк с меткой сценария проверяется, что в ответе есть «врач», «112» или «doctor».

## Гиперпараметры

| Параметр | Значение |
| --- | --- |
| Метод | QLoRA 4 бита, Unsloth |
| r / alpha / dropout | 16 / 16 / 0 |
| Целевые матрицы | q, k, v, o, gate, up, down |
| Длина | 1024 |
| batch × накопление | 1 × 8 |
| Эпохи | 1 (датасет небольшой, вторая эпоха легко зазубривает каталог) |
| lr | 2e-4, AdamW 8 бит |
| Выход | слитые веса и GGUF Q4_K_M |

## Сервер

Прокси слушает 8080, vLLM — только 127.0.0.1:8000. Ключ `Authorization: Bearer`. Лимит `CHIRON_RPM` (по умолчанию 30 запросов в минуту с одного адреса). В журнал не попадают тела запросов.

Дешёвый вариант вместо vLLM: `llama-server -m chiron-q4.gguf --host 127.0.0.1 --port 8000` и тот же `proxy.js` (`UPSTREAM=http://127.0.0.1:8000`). Интерфейс для приложения тот же.

```bash
docker build -t chiron-server chiron-server
docker run --gpus all -p 8080:8080 -e CHIRON_KEY=... -e MODEL=Qwen/Qwen3-8B -e LORA=MaksimSun/chiron-qwen3-lora chiron-server
```

Если 8B не влезает в память карты, поставьте `MODEL=Qwen/Qwen3-4B`.
