# Движок коуча Хирона (lib/coach)

Локальные правила и сценарии: без языковой модели, embeddings и облака. Сообщения и показатели здоровья никуда не отправляются.

## Конвейер (`reply()` в `lib/coachBrain.js`)
1. нормализация (`normalize.js`: регистр, ё→е, пунктуация, повторы букв, частые опечатки и разговорные формы);
2. чувствительное: существующие правила `detect()` (боль, симптомы, лекарства, тяжёлое состояние, вина) + `deathCheck()` (шуточное «умер после тренировки, ахаха» ≠ «боюсь, что умираю, трудно дышать»; сомнение → осторожный ответ с 103/112);
3. NLU (`nlu.js`): признаки (отрицание, прошедшее время, вопрос о прошлом ответе, формат, место, время, вид занятия, «без бега»), продолжения, возможности, ограничения данных, погода, мусор, несколько тем;
4. контекст: `analyze()`, `vars.js` (типизированные переменные: значение/единица/период/источник/время/доступность), `weatherCtx.js`;
5. сценарий (`engine.js` + `scenarios/`) или прежний builder (`A.*`, `B.*`), вариант (`select.js`), сборка (`assemble.js`), проверка (`validate`: нет undefined/null/NaN/`{плейсхолдеров}`/служебных id, длина, ≤1 шутка);
6. юмор (`lib/humor`, отдельная история id) и обновление памяти (`memory.js`).

## Приоритет распознавания (`PRIORITY` в nlu.js)
sensitive_red → sensitive_legacy → joke_about_death → control (короче, подробнее, без шуток, повеселее, проще, повтори, не повторяйся, почему, другой вариант, ладно, спасибо, нет, да) → continuation (по памяти) → pending_answer (ответ на уточнение) → capability → data_limit → legacy_situation → weather → multi_topic → scope → legacy_topic. Команды управления считаются только если ВСЁ сообщение — команда («почему так» — да, «почему шагов меньше» — нет). Подстрока — недостаточное условие.

## Как добавить сценарий и вариант
1. Файл группы в `scenarios/` (схема в `kit.js`): `id`, `group`, `match(nlu, env)`, `variants`, `positives`, `negatives`, при необходимости `humor: [ситуации]`, `sensitive`, `danger`.
2. Вариант — цельный `V(id, ru, en, {humorOk, pending, when})` для чувствительного/сложного или блочный `BV(id, {reaction, main, explain, action, extra, clarify})` для бытового; блок `[ru, en, ['нужные_переменные']]` пропускается, если данных нет. `{steps7|full}` — значение с единицей в нужном склонении.
3. Подключить в `scenarios/index.js`; если нужен маршрут — добавить в `route()` engine.js.
4. Прогнать `checkCatalog()` (тест «целостность каталога»): уникальные id, непустые ru/en, нет точных дублей, известные переменные, у sensitive-сценариев нет юмора.
Правила: 4–6 реально разных вариантов (не косметика), минимум один без юмора; при неизменных фактах рекомендация одна и та же; рекомендации — только из существующей логики приложения.

## Память и неповторяемость
`coachState.v1` (AsyncStorage, `store.js`): тема, сценарий, вариант, последняя рекомендация, ожидаемое уточнение (TTL 2 хода, сбрасывается сменой темы), параметры запроса (место, занятие; TTL 6 ходов), предпочтение краткости, режим юмора, id недавних вариантов (до 40). Текстов сообщений нет. При новом запуске приложения «о чём говорили» не восстанавливается (переписка не хранится), предпочтения и повторы — да. Хранится в `reply().session.memory`. Выбор варианта: из подходящих — тот, что дольше всего не использовался; при равенстве — порядок каталога; без случайности; когда все использованы — самый давний. Id шуток отслеживаются отдельно (`humorId` в истории). Профиль → «Очистить память Хирона» стирает ключ и чат (Health Connect не затрагивается).

## Погода
Только `lib/weather.js` (Open-Meteo, текущие условия и температура, кэш `weather.v1`, TTL 30 мин — `WEATHER_TTL` проверяется тестом). В сервис уходят координаты, округлённые до 0,1°, или название города для геокодинга; данные здоровья и сообщения — нет. Таймаут запроса 8 с. Ошибка/ответ без `current` → отдаётся кэш с `stale:true`. Коуч получает погоду через `setCoachWeather()` и ничего не запрашивает сам.
Политика: слова пользователя > свежие данные (≤ TTL, «по последним данным») > неизвестно; старое/`stale` никогда не «сейчас» (только «последнее сохранённое»); погода другого места не считается местной; прогноза, ветра, осадков, «ощущается как» нет — коуч об этом честно говорит; плохая погода ≠ отмена (зал/дом); гроза/гололёд/жара/мороз — ясная рекомендация первой, шутка только после неё; место спрашиваем один раз и только когда оно влияет; хорошая погода не отменяет ограничений (усталость и т. п.); отказ от геолокации ничего не ломает.
