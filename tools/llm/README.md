# Хирон: бесплатное дообучение и запуск

Платный GPU и vLLM в этот путь не входят. Всё ниже — ноль рублей: Colab или Kaggle для QLoRA, затем свой Always Free сервер Oracle либо бесплатный CPU Space на Hugging Face. Аккаунты этим репозиторием не создаются: ноутбук грузит модель на Hugging Face только если вы сами задали `HF_TOKEN`.

Приложение по-прежнему отвечает каталогом (`lib/coach`, «Подробнее» и источники). Модель — дополнительный голос, не замена правил безопасности.

## Откуда датасет

Сборка: `npx jest --config tools/llm/jest.config.js`

| Источник | Зачем |
| --- | --- |
| `docs/coach-demo-dialogs.md` | 48 диалогов, 168 реплик Хирона. Текст снял `scripts/demoDialogs.js` с живого `reply()`, вручную ничего не дописано. Это основа. |
| `lib/coach/scenarios` | Только фразы пользователя, которых нет в демо: первая чистая реплика сценария и первый вариант без `{плейсхолдеров}`. |
| `lib/coach/qa` | Вопросы кнопками, которых нет в демо: короткий ответ и, если он без плейсхолдеров, «Подробнее». |

Ветка `claude/orchestrator-task-delegation-euwxs5` отдельных файлов с персоной или диалогами не добавляет: набор файлов там совпадает с `main`. `tools/intent/data/*.jsonl` — это классификатор намерений (опечатки и метки), не диалоги. В LoRA он не входит.

Системная реплика в jsonl короткая: наставник Epimely, язык человека, 1–3 предложения, без диагноза и без выдуманных цифр. Строка приветствия «без языковой модели» в демо оставлена как есть: так отвечает сегодняшний каталог.

Файлы: `tools/llm/data/train.jsonl`, `val.jsonl`, `stats.json`.

## Какой размер учить

Свободная машина Oracle Always Free — до 4 OCPU и 24 ГБ ARM. Узкое место — скорость CPU, не память: Q4_K_M на 4B занимает около 2,5 ГБ. Цифры ниже — оценки по публичным замерам llama.cpp на Ampere A1 и на 2 vCPU Spaces, не замер этого репозитория. Разброс большой: зависит от сборки, потоков и длины промпта.

| Где | Модель Q4_K_M | Оценка, ток/с | Ответ ~80 токенов |
| --- | --- | --- | --- |
| Oracle A1, 4 OCPU | Qwen3-0.6B | 20–40 | 3–6 с |
| Oracle A1, 4 OCPU | Qwen3-1.7B | 10–18 | 6–12 с |
| Oracle A1, 4 OCPU | Qwen3-4B | 4–8 | 15–30 с |
| Hugging Face Space, бесплатный CPU (2 vCPU, засыпает) | 0.6B | 8–15 после холодного старта 20–60 с | терпимо |
| Тот же Space | 1.7B | 3–8 | уже тянется |
| Тот же Space | 4B | 2–4, память впритык | не стоит |

Рекомендация: учить **Qwen3-1.7B** и отдавать его с Oracle. 0.6B — если нужен ответ за несколько секунд и голос можно сделать проще. 4B на бесплатном T4 в Colab учится, но на бесплатном ARM отвечает десятки секунд; для Space его не брать.

На бесплатном T4 (16 ГБ) QLoRA 4-бит, длина 1024, batch 1: 0.6B — порядка 10–20 минут, 1.7B — 20–45 минут, 4B — около часа на этот датасет (один проход). Если 4B не влезает, в ноутбуке стоит переключить константу на 1.7B. Kaggle выдаёт T4 или P100 и лимит около 30 часов GPU в неделю; P100 для Unsloth хуже, при ошибке ядра переключитесь на T4.

## Обучение

- Colab (бесплатный T4): `tools/llm/colab_qlora.ipynb`
- Kaggle (бесплатный GPU): `tools/llm/kaggle_qlora.ipynb`

Оба ставят Unsloth, учат QLoRA, сохраняют слитую модель и GGUF **Q4_K_M**. Выгрузка на Hugging Face выполняется только при своём `HF_TOKEN`.

## Запуск без платы

### Oracle Cloud Always Free (основной)

Образ Ubuntu на Ampere A1, 4 OCPU, 24 ГБ. В консоли Oracle лимит бесплатных ядер иногда занят в регионе — это ограничение квоты, не счёт.

```bash
sudo apt update && sudo apt install -y build-essential cmake git
git clone https://github.com/ggerganov/llama.cpp && cd llama.cpp
cmake -B build -DGGML_NATIVE=ON && cmake --build build -j4 --target llama-server
```

Модель положить в `~/chiron.gguf` (скачать свой GGUF с Hugging Face). Сервер слушает только localhost, ключ — длинная случайная строка:

```bash
./build/bin/llama-server -m ~/chiron.gguf -c 1024 -t 4 --host 127.0.0.1 --port 8080 --api-key "$CHIRON_KEY"
```

Снаружи — Caddy из пакетов Ubuntu (бесплатно), HTTPS и прокси на localhost. Заголовок `Authorization: Bearer …` проверяет сам llama-server (`--api-key`). Отдельный платный шлюз не нужен. Порт 8080 в интернет не открывать.

Проверка: `curl -H "Authorization: Bearer $CHIRON_KEY" http://127.0.0.1:8080/v1/chat/completions` с телом OpenAI.

### Hugging Face Spaces, бесплатный CPU (запасной)

Space типа Docker, 2 vCPU. В контейнере тот же `llama-server` и ваш GGUF 0.6B или 1.7B. Space засыпает: первый запрос после паузы ждёт полминуты–минуту. Для 4B этот вариант не рекомендуется. Секрет `CHIRON_KEY` задаётся в настройках Space, не в репозитории.
